# Архитектура fogmap

## 1. Выбор платформы: Kotlin, не React Native

Решение принято, к нему не возвращаемся без новых данных.

Разница между RN и native не в UI, а в трёх местах:

| Задача | Kotlin | React Native |
|---|---|---|
| Фоновый трекинг GPS | Foreground Service + `FusedLocationProvider` | нативный модуль (то есть тот же Kotlin) либо платный `react-native-background-geolocation` |
| Перекраска маски тумана на каждый кадр камеры | `Canvas` / GL напрямую | через JS-бридж → лаги |
| Побитовые операции над маской (popcount, OR) | нативно | `Uint8Array` в JS, медленно |

RN дал бы iOS «почти бесплатно», но с нативным модулем на каждую из трёх задач экономия исчезает.
iOS — после того как Android-версия заработает.

## 2. Структура репозитория

```
fogmap/
├── CLAUDE.md
├── docs/
│   ├── ARCHITECTURE.md
│   └── ROADMAP.md
├── android/
│   ├── app/                    # Compose UI, FogStore, TrackingService
│   ├── core/
│   │   ├── fog/                # pure JVM: FogMask, тайловая индексация, площадь
│   │   ├── track/              # pure JVM: отбраковка фиксов, достройка пути
│   │   └── routing/            # pure JVM: clipRoute, ресемплинг, гистерезис (M3)
│   └── data/                   # Room, Retrofit, репозитории, sync
└── backend/
    ├── src/main/java/.../fogmap/
    │   ├── auth/               # регистрация, логин, JWT, refresh
    │   ├── fog/                # /fog/sync, OR-merge, пересчёт площади
    │   ├── social/             # друзья, лидерборд
    │   ├── achievement/        # правила и выдача
    │   └── routing/            # прокси к движку маршрутов
    └── src/main/resources/db/migration/   # Flyway
```

`core:*` — без Android SDK. Это осознанно: вся геометрия и вся логика отбраковки фиксов тестируются
обычным JUnit, без эмулятора.

Сервис трекинга живёт в `:app`, а не в отдельном модуле, как задумывалось изначально. Причина: он и
экран карты делят один `FogStore`, и вынос сервиса потребовал бы интерфейса и внедрения зависимости
ради одной реализации. Чистая часть — отбраковка и достройка — всё равно вынесена в `core:track`,
так что тестируемость от этого не пострадала.

**`FogStore`** — единственный владелец маски на процесс. И трекер, и тап по карте пишут в него, все
методы вызываются с main-потока: рендер читает маску синхронно в `onDraw`, и любой другой
поток-владелец потребовал бы копий или блокировок на каждом кадре. Вскрытие стоит доли миллисекунды,
так что main это выдерживает.

## 3. Модель тумана

**Тайл + битовая сетка.**

- Мир разбит на тайлы Web Mercator z=14. Внутри тайла — сетка 256×256 бит, 8 КБ на тайл.
- Размер ячейки на земле: `40075017 × cos(lat) / 2^14 / 256`.
  На широте 56° это ≈ 5.4 м, на равноторе ≈ 9.6 м. Ячейки мельче к полюсам — это нормально,
  просто площадь считается с поправкой на широту тайла.
- «Открыть точку» = закрасить в маске круг радиусом `REVEAL_RADIUS_M = 60`.
- Хранение: Room, `fog_tile(x, y, mask BLOB, revealed_cells, updated_at, dirty)`.
  Маска сжимается хорошо (области почти всегда сплошные) — жать при отправке на сервер, не в БД.
- Площадь: `revealed_cells × cell_area_m2(tile_y)`, суммируется по тайлам. Инкрементально
  обновляется при каждом изменении маски, полный пересчёт не нужен.

**Рендер — два слоя:**

1. Статичный туман: маска → PNG-тайлы, отдаются локальным tile provider'ом (мини-HTTP на
   `127.0.0.1`), MapLibre тянет их как обычный raster source. Плюс — нет рассинхрона с картой при
   жестах и инерции, зум работает сам. Минус — нужна инвалидация кэша тайлов при изменении маски.
2. Живой круг вокруг текущей позиции — отдельным слоем сверху, обновляется на каждом фиксе.

Туман непрозрачный: под ним не видно ничего. Отсюда требование, которое легко сломать случайно —
**логотип MapLibre и кнопка атрибуции должны оставаться поверх тумана**. Атрибуция данных OSM
обязательна по ODbL, поэтому оверлей вставляется ребёнком `MapView` по фиксированному индексу
(над GL-поверхностью, под служебными вьюхами карты), а не последним в списке.

Чтобы туман читался туманом, а не серым прямоугольником с ровными дырками, маска перед отрисовкой
проходит три шага (`FogTexture`):

1. **Размытие границы.** Box-размытие радиусом 3 ячейки (~16 м) превращает бит в покрытие 0..1.
   Считается по глобальным координатам с полями из соседних тайлов — иначе размытие упирается в
   край тайла и на стыках проступает сетка. Поля берутся вдвое шире радиуса: у внешней полосы
   бегущие суммы неполные, и это не должно дотягиваться до центральной области.
2. **Рваный край.** Порог границы смещается значением шума, привязанного к глобальным координатам
   ячеек, — окружность превращается в клочья, и на стыках тайлов нет швов. Ячейки, где покрытие
   строго 0 или 1, шум не считают вовсе: это ранний выход, который держит построение тайла в
   единицах миллисекунд. Он корректен, только пока амплитуда шума меньше удвоенного нижнего
   порога, — константы связаны, менять по отдельности нельзя.
3. **Облачная заливка.** Тайлящийся шум 512×512, повторяемый шейдером. Контраст намеренно низкий:
   при высоком глаз начинает читать повторяющуюся плитку вместо облаков.

Размытие читает ячейки за краем тайла, поэтому при изменении тайла кэш битмапов сбрасывается и у
восьми его соседей. Пересчёт ленивый — строятся только видимые тайлы.

Альтернатива для прототипа: `View` поверх `MapView` с `PorterDuff.CLEAR` и синхронизацией через
`map.projection`. Проще на пару часов работы, но подрагивает на инерционном скролле. Решаем
замером на M1, а не спором.

## 4. Маршруты с учётом тумана

**Движок:** GraphHopper Core (Apache-2.0) встроенный в Spring-бэкенд — это Java-библиотека, отдельный
сервис не нужен, грузит `.pbf` региона. Для прототипа можно публичный OSRM, но у него нет SLA и
только автомобильный профиль, в релиз он не идёт.

**Отсечение по туману** (`core:routing`):

```
1. Ресемплировать геометрию маршрута с шагом ≈ размеру ячейки маски (15 м).
   Более крупный шаг теряет границы тумана, более мелкий ничего не добавляет.
2. Для каждой точки — битовый lookup в маске, O(1).
3. Склеить подряд идущие точки с одинаковым флагом в сегменты (run-length).
4. Сгладить: сегмент короче MIN_SEGMENT_M = 80 наследует тип соседей.
```

Шаг 4 обязателен. Без него на границе открытой территории маршрут превращается в мерцающий пунктир
из 15-метровых кусочков — маска не идеально ровная, и линия многократно пересекает край.

**Отрисовка:**

- Открытая часть — обычная линия маршрута.
- Скрытая часть — разреженные точки-«крошки» каждые ~300 м вдоль сегмента. Видно направление и
  примерную длину, но не геометрию улиц.
- Точка назначения — маркер всегда, даже в тумане: её выбрал сам пользователь.

Почему крошки, а не «вообще ничего в тумане»: второй вариант честнее к идее fog of war, но ломает
основной сценарий — «дойти до нового места». Крошки — компромисс, по которому реально можно идти.
Если геймплейно захочется жёстче, это одна константа.

## 5. Бэкенд

Нужен, но **не для карты**. Правило: туман локально, сервер — только социальное.

Java 21, Spring Boot 3, Postgres, Flyway. PostGIS не нужен — маска не геометрия, а blob.

### Эндпоинты

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/auth/register`, `/auth/login`, `/auth/refresh` | JWT (access ~15 мин) + rotating refresh |
| POST | `/fog/sync` | загрузка изменённых тайлов, в ответ — тайлы с других устройств юзера |
| GET/POST | `/friends`, `/friends/requests` | заявки, подтверждение, список |
| GET | `/leaderboard?scope=global\|friends` | по площади |
| GET | `/achievements` | разблокированные + прогресс |
| POST | `/routes` | прокси к GraphHopper (ключи и .pbf не в APK) |

### Схема

```sql
users            (id, username UNIQUE, email UNIQUE, password_hash, created_at)
refresh_tokens   (id, user_id, token_hash, expires_at, revoked_at)
fog_tiles        (user_id, x, y, mask bytea, revealed_cells int, updated_at,
                  PRIMARY KEY (user_id, x, y))
user_stats       (user_id PK, area_m2 bigint, tiles_count int, updated_at)
friendships      (requester_id, addressee_id, status, created_at,
                  PRIMARY KEY (requester_id, addressee_id))
achievements     (code PK, title, description, metric, threshold)
user_achievements(user_id, code, progress, unlocked_at, PRIMARY KEY (user_id, code))
tracks           (id, user_id, started_at, ended_at, distance_m, points_count)
```

`revealed_cells` денормализован специально: лидерборд не должен декодировать блобы.
`user_stats.area_m2` — материализованная сумма, обновляется в той же транзакции, что и `/fog/sync`.

### Синхронизация

Маска grow-only → merge = `mask_server | mask_client`. Идемпотентно и коммутативно, порядок
запросов не важен, конфликтов нет. Повторная отправка того же тайла ничего не меняет — можно
ретраить свободно.

### Античит

Это не паранойя: площадь и ачивки — единственное, за что в такой игре есть смысл читерить, и
подмена одного числа в запросе даёт первое место в лидерборде.

1. Сервер считает `revealed_cells` и площадь **сам**, из присланного блоба. Числа от клиента
   игнорируются полностью.
2. Валидация трека на телепорты: скорость между соседними фиксами > 200 км/ч → сегмент не
   засчитывается в открытие.
3. Rate limit на `/fog/sync` — открытие огромной площади за секунду физически невозможно.

Полностью защититься от mock location нельзя, и не надо — цель в том, чтобы читерство требовало
осознанной работы, а не одного HTTP-запроса.

### Почему не Firebase/Supabase

Auth и БД они закрыли бы быстрее. Но серверный пересчёт площади и валидацию треков всё равно
пришлось бы писать своим кодом (Edge Functions), так что Spring оправдан — и остаётся один язык
для роутинга (GraphHopper тоже Java).

## 6. Тайлы

Ключевое ограничение — см. инвариант 1 в [CLAUDE.md](../CLAUDE.md): публичный tile-сервер OSM
использовать нельзя.

| Вариант | Когда |
|---|---|
| **OpenFreeMap** | MVP. Бесплатно, без лимитов и без API-ключа, стили Liberty/Bright/Positron. Держится на донатах, SLA нет — как основа для релиза рискованно. |
| **Protomaps / .pmtiles** | Целевой вариант для офлайна: один файл на регион (город ~50–200 МБ), раздаётся с nginx/S3 через Range-запросы, сервер тайлов не нужен вообще. Перед выбором проверить актуальное состояние поддержки pmtiles в maplibre-native на Android. |
| **MapTiler** | 100k тайлов/мес бесплатно, дальше платно. Нужен ключ → ограничивать по package name + SHA подписи. |
| **Свой сервер** | `planetiler` (один Java-jar) генерирует pmtiles/mbtiles на страну за минуты, дальше nginx или TileServer GL. Максимум контроля, минимум зависимости от чужого uptime. |

План: **OpenFreeMap на M1 → своя генерация planetiler + pmtiles к M6.** Смена провайдера — это
смена style URL, поэтому решение не блокирующее и его не надо принимать сейчас окончательно.

Офлайн-регионы: `OfflineManager` MapLibre работает с любым источником, так что скачивание городов
доступно и на OpenFreeMap.
